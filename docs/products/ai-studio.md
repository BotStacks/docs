AI Studio is the product area for shaping assistant behavior. In the current app, open **Assistants**, select an assistant, and use its workspace tabs. You do not need to build a complex workflow to start with a useful website FAQ assistant.

## Find the right tab
| Tab | Purpose |
| --- | --- |
| Blueprint | Review the selected assistant's definition |
| Configure | Preview and apply a plain-language behavior change |
| Workflows | Edit and publish conversation paths |
| Skills | Review the assistant's skills surface where available |
| Bot Design | Customize the visitor experience and continue to deployment |

Knowledge and DIRTbox are workspace-level destinations. Always confirm the assistant selection when moving between them.

## Preview a configuration change
1. Open **Configure** for the intended assistant.
2. Describe one focused change, such as “Keep replies brief and direct visitors to our contact page when pricing is missing.”
3. Select **Preview** and review the proposed changes.
4. Select **Apply** only if the preview is understood and matches your intent.
5. Test the changed behavior in DIRTbox.

Preview does not save the change. A configuration save is also not proof that the published website behaves correctly; verify the visitor experience after your release process.

## Keep promises bounded
Do not tell the assistant it can book, refund, charge, or access accounts unless that action is configured and verified. A contact link is different from a staffed live handoff. Set a clear fallback for missing information.

For structured routing, see [Workflows](/products/workflows). For facts, use [BrainVault](/products/brainvault).
