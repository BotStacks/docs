## Build a small acceptance set
Test at least these scenarios with your own content. Record the question, expected answer source, observed response, and whether it passed.

| Scenario | What a useful response does |
| --- | --- |
| Common service or product question | Gives an accurate answer from current content |
| Same question in different words | Preserves the meaning and answer |
| Missing information | Says it does not know and provides a contact route |
| Policy exception | Does not invent a promise |
| Unrelated request | Returns to the assistant's purpose |
| Request for private account information | Does not claim access it does not have |

## Check the published website
After following your workspace's deployment instructions, open the published site in a private browser window. Check phone and desktop layouts, keyboard access, chat close controls, cookie banners, navigation, and important purchase or booking buttons.

Confirm that the assistant displayed is the intended one and that contact links work. Test your acceptance set again on the live site; a DIRTbox result alone does not verify website installation.

## Keep a rollback route
Know how to remove or disable the embed in your CMS before launch. If answers are misleading or the widget blocks a critical action, remove it while you correct and retest the issue.
