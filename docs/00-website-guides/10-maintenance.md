## Review after website changes
When prices, policies, services, or opening hours change, update the source content and refresh the affected knowledge using the controls in your workspace. Re-run the questions that depend on those sources.

## Diagnose the symptom
| Symptom | First check | Next step |
| --- | --- | --- |
| Wrong or outdated answer | Source text and duplicate versions | Update knowledge, then retest in DIRTbox |
| Missing answer | Whether the relevant content was imported | Add or correct an approved source |
| Widget does not appear | Published CMS page and actual deployment instructions | Check publishing, plan restrictions, and consent settings |
| Works in testing but not on the website | Assistant identity and published configuration | Repeat the same question in both places |
| Widget overlaps a button | Small-screen placement | Adjust placement or disable until corrected |

## Ask for help with useful evidence
Send your public page URL, platform, time of failure, expected behavior, and a redacted screenshot to [support@botstacks.ai](mailto:support@botstacks.ai). Remove visitor details, tokens, and credentials. Do not submit private conversations without authorization.

## Keep a lightweight review routine
Assign an owner. Review common unanswered questions and content changes weekly. Record fixes and re-test before expanding the assistant's scope.
